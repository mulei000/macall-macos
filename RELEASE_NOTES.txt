================================================================================
macall — 源码快照 / 发布说明
================================================================================

版本    : v0.5.0 (build 78)
日期    : 2026-08-10
保存原因: 性能与资源占用优化（不影响功能 / UI）。

--------------------------------------------------------------------------------
一、本版本（build 78）变更
--------------------------------------------------------------------------------

1. 监控模块隐藏时智能调度采样（SystemMonitor 常驻占用优化）
   - MonitorFeature 监听 statusBarModuleOrder / statusBarHiddenModules / 通知阈值开关变化，
     与 StatusBarManager.visibleModules 同口径判断监控是否整体不可见。
   - 显示 → 正常 2s 采样。
   - 隐藏 + 有任意通知阈值启用 → 降频到 10s，保留阈值通知。
   - 隐藏 + 无通知阈值 → 完全停止采样（monitor.stop()），省 CPU。
   - 默认监控模块全显示，故默认行为不变（仍 2s 采样）。

--------------------------------------------------------------------------------
二、历史版本（build 77）变更
--------------------------------------------------------------------------------

1. 音频进程监控兜底轮询自适应降频
   - AudioProcessMonitor 周期刷新：当前无活跃音频 App 时，兜底轮询从 10s 放宽到 30s；
     一旦有 App 出声，逐进程 isRunning 监听会立即触发 refresh()，实时性不受影响。
   - 仅在活跃 App 集合真正变化时才打印 [perapp] 日志（之前每轮都打印，徒增磁盘 IO）。

2. 系统监控能耗扫描后台化
   - SystemMonitor 每 2s 轮询原在主线程同步 waitUntilExit() 一个 /bin/ps 子进程（读能耗 Top），
     周期性阻塞菜单栏刷新。改为 .utility 后台线程计算，结果回主线程合并进 snapshot。
   - 数据更新只比其它指标晚一拍（同一次轮询内补齐），UI / 通知行为不变。

--------------------------------------------------------------------------------
二、历史版本（build 76）变更
--------------------------------------------------------------------------------

1. 音量弹窗整体宽度窄 10%
   - VolumePopoverMetrics.width 从 420 改为 378。

2. 修复主音量卡片标题右侧设备名被截断
   - 问题：IadenteCard 标题栏默认让 IadenteSectionHeader 占满左侧空间，把右侧设备胶囊压得很窄，
     即使空间足够也显示成 "MacBook Air扬...""。
   - 改法：
     - IadenteCard 新增 trailingSpacer 参数（默认 true，不影响设置页等现有卡片）。
     - 主音量卡片传入 trailingSpacer: false，让标题只占用必要宽度，右侧设备胶囊获得其自然宽度。
     - masterVolumeHeaderDevices 内部文本宽度从 geo.size.width * 0.66 放宽到 geo.size.width - 8，
       允许设备名占满胶囊区域。

二、历史版本（build 75）变更

三、历史版本（build 74）变更
--------------------------------------------------------------------------------

1. 设置页开关右对齐

三、历史版本（build 73）已实现的功能状态
--------------------------------------------------------------------------------

1. 逐 App 音量接管（核心）
   - 借用 FineTune 开源方案：CoreAudio ProcessObjectList + 逐进程
     kAudioProcessPropertyIsRunning 判断 + responsibility_get_pid_responsible_for_pid
     解析责任进程（正确归并 Safari/Chrome helper 到宿主 App）。
   - 完全删除 MediaRemote 私有 API 依赖（实测在沙箱/权限环境下拿不到数据）。
   - 系统层音量接管：静音 App 后经由 macall 的 CATap 以 0…2 增益重渲染，
     不动 App 自身滑块（满足"系统层接管"需求）。

2. 检测增强（build 70 起）
   - 逐进程"正在出声"监听：App 开声/停声 ~1s 内刷新列表，不再干等 10s 轮询。
   - 变化检测（AppFingerprint）：App 集合未变时不通知上层，避免 UI / tap 抖动。

3. 列表净化（build 71 起）
   - 从源头丢弃"无真实宿主 App 且无手动开启"的游离进程（如 Chrome helper）。
   - 系统守护进程（CoreSpeech 等）双保险过滤。
   - 清掉历史残留的隐藏记录；"隐藏"按钮对守护/游离进程失效。

4. App 卡片 UI（build 72 起，两行精简）
   - 第一行：图标 + 名称/设备名(可点击 Menu 选输出设备) + 静音/均衡器/隐藏/接管开关 图标。
   - 第二行：音量条 + 百分比（仅接管后显示）。
   - 均衡器改为图标（开=主题色高亮，关=灰），点开展开 10 段 EQ 滑杆。
   - 设备选择 Menu 去掉了重复的向下三角（只留一个）。
   - 不再有独立"忽略"按钮（关掉接管开关即等于取消接管）。

5. 隐藏设备功能（build 73 起）
   - 输出设备卡片每行右侧"眼睛(带斜杠)"图标可隐藏设备，底部"已隐藏的设备(N)"可折叠区。
   - 隐藏只影响 macall 弹窗显示，不触碰系统音频；可单独恢复或一键全部恢复。
   - 单 App 路由的设备 Menu 未过滤隐藏设备（按需可另行添加）。

6. 状态栏监控图标与音量图标
   - 监控图标 = 裸 SwiftUI 文字视图（电池/温度/功率等），无任何自定义底色/圆角，
     直接浮在菜单栏背景上（系统默认渲染，深色/浅色菜单栏自动反色）。
   - 音量图标 = 纯模板 NSImage（speaker.*.fill），透明底，随菜单栏反色。
   - 注意：两者均无 macall 自绘的"蓝紫胶囊底"。截图中看到的底色差异是
     系统对"文字视图 vs 模板图标"的默认渲染差异，并非主动设置。
     （后续若要做统一胶囊底，需新增背景层，见"待办"。）

--------------------------------------------------------------------------------
二、构建与部署
--------------------------------------------------------------------------------

- 构建：bash build.sh  （swiftc 直编，避开 swift build sandbox 限制）
- 版本号唯一来源：build.sh 顶部 APP_VERSION_NUM / APP_BUILD
- 默认产物：~/Desktop/macall.app
- 部署到 /Applications：先 rm -rf /Applications/macall.app 再 cp -R
  （重要：BSD cp -R 在目标已存在时会嵌套，务必先删后拷）

三、已知边界 / 待办
--------------------------------------------------------------------------------

- [待定] 状态栏两个图标"统一胶囊底/圆角"：当前代码无自定义底，需新增背景层。
        方案：在 StatusBarContentView.body 外包 Capsule/material 背景；
        底色风格（主题蓝紫实心 vs 系统 material）与圆角（Capsule vs 固定圆角）待用户定。
- [未移植] FineTune 的高级音频引擎（EQ 完整实现/AutoEQ 联网/响度补偿/跨设备淡入淡出/
        输出门软启动/聚合设备规划）：当前仅用 0…2 增益 + 软限幅路径，稳定工作，
        大改风险高，列为后续候选（用户曾要求"全部移植"，但被更优先的 UI 调整打断）。
- [未做] 单 App 音频"暂停键"：macOS 无通用暂停 API（MediaRemote 不通用、AppleScript
        各 App 命令不一、SIGSTOP 副作用大），已决定不做，静音图标等价于无声。

四、日志与排障
--------------------------------------------------------------------------------

- 弹窗定位：grep "\[popover\]" ~/Library/Logs/macall/macall.log
- 权限首检：grep "\[permission\]" ~/Library/Logs/macall/macall.log
  （辅助功能权限失效 = 全局快捷键/窗口操作/边缘吸附/Dock 扫描同时静默死掉）
